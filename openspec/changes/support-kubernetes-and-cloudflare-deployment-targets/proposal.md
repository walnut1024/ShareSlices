# Support Kubernetes and Cloudflare deployment targets

<!-- cspell:words Hyperdrive -->

## Why

ShareSlices has rendered Kubernetes examples but no product-supported release, verification, or rollback lifecycle. Its resident Node and Rust process composition also needs explicit runtime seams before it can use Cloudflare Workers, Queues, R2, Hyperdrive, and Containers without duplicating product policy.

The product needs two mutually exclusive production deployment targets: a cloud-vendor-neutral Kubernetes target and a Cloudflare-managed target whose bounded processing can scale to zero. The repository's canonical Docker Compose development stack also needs clear ownership under `deploy/` while retaining the local behavior defined by the separate `local-development-stack` capability.

## What Changes

- Introduce two first-class, mutually exclusive production deployment targets selected when an installation is configured: a cloud-vendor-neutral Kubernetes target for an existing conforming cluster, and a Cloudflare target composed from Cloudflare-recommended runtime services. Neither target depends on deploying the other target's runtime composition.
- Treat this change as the intended post-change support contract, not evidence that either target is already available. A release may advertise a target only after its implementation and target-specific qualification gates pass; a failed Cloudflare gate does not block an independently qualified Kubernetes release.
- Make `deploy/` the repository owner of deployment composition and automation. Provide one non-interactive production `doctor`, `render`, `plan`, `apply`, `status`, `verify`, and `rollback` lifecycle with validated inputs, redacted output, immutable release evidence, durable operation fencing, release inventory and retirement, and target-specific Adapters.
- Consolidate the checked Docker Compose definitions, local proxy configuration, lifecycle implementation, and test fixtures under `deploy/compose/` and `deploy/automation/` while preserving `mise run dev`, `dev-status`, `dev-logs`, and `dev-down` as the only supported local lifecycle. Compose remains a non-production development/test topology, uses local PostgreSQL, private S3-compatible storage, and Mailpit SMTP, follows the new runtime-role seams, and runs automated integration tests through the dedicated test-only project without mutating the developer stack.
- Upgrade Kubernetes from example manifests to a supported deployment path using external PostgreSQL, private S3-compatible storage, and an operator-provided enterprise SMTP relay. It can use direct ingress or an optional external CDN; enabling a CDN does not select or combine the Cloudflare runtime target.
- Add the Cloudflare target while reusing the same product behavior, HTTP and database contracts, object layout, durable job, lease, fence, attempt, and idempotency semantics, isolated untrusted-content policy, and cache policy as Kubernetes.
- Make Cloudflare Edge/CDN an explicit target module rather than an implicit property of Static Assets. Content-hashed Web assets are edge-cacheable; optional Viewer content acceleration may cache only bounded full immutable Version representations behind an authorization-first Worker route. Range responses bypass that internal cache, while API, authentication, management, Upload, Preview, stable Viewer, known-link state, and authorized Gallery routes remain non-cacheable.
- Qualify the Cloudflare target against pinned official platform contracts instead of assuming generic serverless compatibility. A release-only, route-free verifier harness uses an isolated temporary Queue and fetch-based Service Bindings to prove zero-percent App/Content versions and the Jobs/database/broker/Container path without adding a public probe endpoint or reusing product triggers. The target requires a Workers Paid entitlement for Containers and must reject an installation when account limits, Worker runtime compatibility, database reachability, Container isolation, target-specific Secret deployment and rotation, or provider API support cannot satisfy the configured ShareSlices contract. Plans report bounded cost-driving settings and quota evidence without promising a fixed or free bill.
- Make email delivery a target Adapter over the existing durable authentication-email contract: Kubernetes uses an operator-provided enterprise SMTP service, while Cloudflare uses the Resend HTTPS API and an operator-provided Resend account, verified sending domain, disabled authentication-email tracking, and scoped API key. Provider acceptance remains distinct from final inbox delivery; each attempted delivery is pinned to one provider namespace and payload across retries; and Resend's finite idempotency window does not replace ShareSlices durable delivery state.
- Refactor runtime composition only where two real deployment Adapters require it, including independently deployable HTTP, maintenance, content-only, and bounded or resident background-processing roles. These seams MUST NOT create a second business-policy implementation.
- Split Cloudflare thumbnail authorization into a browser-visible read-only capture capability and a separate controller/output capability that never enters Artifact-visible surfaces.
- Validate both targets against one machine-readable black-box contract for routes, status codes, headers, credentials, caching, readiness, job recovery, and Gallery isolation. A target may enable Gallery only when the existing deployment-eligibility contract succeeds against its actual topology.
- Add application release automation that builds immutable target artifacts once, records their digests and compatibility metadata, validates current/previous (`N`/`N-1`) runtime and schema compatibility, and deploys them through thin CI entrypoints.
- Define operator-owned release stores and recoverability evidence for PostgreSQL, object storage, Infrastructure as Code (IaC) state, release bundles, and deployment journals; disaster recovery remains distinct from application rollback.
- **BREAKING (deployment interface only)**: replace the current directly applied Kubernetes example overlays, fixed service addresses, mutable image tags, and deployable placeholder Secret with a validated deployment configuration and generated release bundle. The canonical local Compose commands, origins, data-retention behavior, and developer/test isolation contract remain stable, while unsupported direct file paths and internal orchestration may move under `deploy/`.

## Out of Scope

- Running Kubernetes and Cloudflare runtime compositions together for one installation, active-active operation, cross-target failover, or automatic migration of a live installation between targets.
- Creating EKS, GKE, AKS, VPCs, Cloudflare accounts, external PostgreSQL, object-storage accounts, enterprise SMTP services, Resend accounts, or Resend sending domains.
- Making Cloudflare a required dependency of the Kubernetes target. A Kubernetes installation using Cloudflare only as an external CDN remains the Kubernetes target and does not deploy Cloudflare application Workers or processing Containers.
- Adding a database engine, changing PostgreSQL as the business source of truth, or automatically reversing database migrations and durable data during application rollback.
- Caching Preview, stable Viewer responses, known-link state, authorized Gallery content, or other responses governed by an existing `no-store` contract. Optional Cloudflare Viewer acceleration caches only a separate full immutable Version representation under an internal version, path, and representation identity after current Publication authorization; it does not cache or bypass the stable Viewer response and does not cache Range responses.
- Promoting Compose to a third production target, accepting `target: compose`, exposing production release lifecycle commands for Compose, or treating a local Compose pass as Kubernetes or Cloudflare qualification.
- Changing Artifact, Publication, Gallery, Web, end-user CLI, or public OpenAPI product semantics, or changing account-entry HTTP and user-visible flows. The account-entry change is limited to the internal and operational authentication-email delivery outcome contract needed by the target-specific SMTP and Resend Adapters. The deployment-internal broker and release-verification wire contracts listed under Impact remain private and do not add a public product surface.

## Capabilities

### New Capabilities

- `deployment-orchestration`: Mutually exclusive production target selection, an explicit boundary from the separately owned local Compose topology, validated deployment configuration, immutable release bundles, common production lifecycle commands, Secret revision handling, fenced deployment operations, release inventory and retirement, status, verification, compatibility-aware rollback, and deployment records.
- `kubernetes-deployment`: Installation into an existing standard Kubernetes cluster, deterministic phased Kustomize rendering, workload and migration composition, ingress and Gallery isolation, production hardening, direct reconciliation, render-only GitOps handoff, and optional external CDN behavior.
- `cloudflare-deployment`: Cloudflare Edge/CDN policy, Workers, Static Assets, private R2, Hyperdrive, Queues, scheduled triggers, Containers, isolated content routing, versioned rollout, and bounded-processing composition while retaining PostgreSQL as the durable source of truth.

### Modified Capabilities

- `account-entry`: Extend the provider-neutral durable authentication-email outcome contract with provider-acceptance classification, optional provider identifiers, an immutable per-delivery transport-namespace snapshot, bounded provider idempotency, and signed, transactionally serialized manual reconciliation after a finite deduplication window expires or a non-idempotent transport loses its final post-submission response.
- `artifact-viewer`: Extend deployment-address portability from Compose and Kubernetes forms to the Cloudflare target, preserve dynamic Viewer and revocation semantics, and permit target-local acceleration of immutable Version bytes only behind current Viewer authorization.
- `artifact-thumbnail`: Express thumbnail execution isolation as a platform-neutral security outcome, preserve the single-use capture bootstrap through a separate short-lived read-only browser session, retain the concrete hardening requirements for operator-managed containers, and require equivalent evidence for Cloudflare Containers.

## Impact

- Deployment automation and contracts under `deploy/`, including migration of root Compose inputs and local/test controllers into the Deployment Module without changing the supported `mise` lifecycle; repository task entrypoints in `.mise.toml`; and thin application release/deployment workflows under `.github/workflows/`.
- Change-order dependency on completing and archiving `consolidate-local-development-stack` before moving Compose files or ownership. This change preserves that capability's implemented behavior unless implementation first adds an explicit `MODIFIED` delta.
- Kubernetes manifests and checks, including replacement of fixed ClusterIPs, placeholder Secret data, per-Pod migration init containers, incomplete public routing, and configuration checks that currently validate only a cross-workload variable union.
- API composition and infrastructure Adapters under `api/src/`: role-specific configuration, Node and Cloudflare entrypoints, HTTP versus maintenance execution, PostgreSQL connection modes, private object storage, email delivery, trusted ingress metadata, and isolated content composition.
- Authentication-email delivery Adapters and deployment checks: SMTP for Kubernetes, Resend HTTPS for Cloudflare, with shared durable leases, retries, idempotency, circuit breaking, and payload-deletion behavior.
- Provider-qualification evidence and compatibility tests for the pinned Wrangler, Cloudflare Terraform provider, Workers compatibility date, Container and versioned-Secret contracts, Kubernetes API and CNI prerequisites, and Resend HTTP contract. External quotas, plan limits, and provider-side message retention remain deployment facts rather than ShareSlices guarantees.
- Worker composition under `worker/`: resident and bounded-drain Runners over the same processing Modules, all job lanes, graceful termination, and Queue wake-up integration without changing durable job authority.
- Thumbnail execution and internal-capture wiring, preserving bounded Chromium rendering, blocked public egress, private capture access, and platform-equivalent container isolation.
- Web release configuration under `web/`, including environment-neutral build output and deployment-provided public configuration.
- Cloudflare edge routing and cache policy, including automatic Static Assets delivery, generated asset headers, an optional authorization-first full-body Viewer byte cache, explicit Range/dynamic-route bypass, private R2 enforcement, and cache verification and purge drills.
- PostgreSQL migrations and release metadata checks for immutable migration checksums and N/N-1 expand/contract compatibility; no automatic down migration is introduced.
- Durable architecture and operator documentation in `PRODUCT.md`, `CONTEXT.md`, `docs/design/modules.md`, `docs/operations/`, and the repository deployment map.
- No public product HTTP route, public OpenAPI payload, or end-user CLI behavior change is proposed. The private thumbnail execution broker and route-free Jobs release-verification probe are deployment-internal HTTP protocols: their versioned wire contracts remain checked under `api/openapi/`, are projected into `deploy/contract/`, and are unreachable through public ingress. Any other discovered contract change must be specified before implementation continues.
